// approach

What I believe about testing

// 01

A green test should mean the data is right, not just the screen.

UI assertions are easy to fool. I validate against the database and API layer so a pass actually means the system did the right thing end to end.

// 02

Flaky tests are bugs. I fix them — I don't re-run them.

A suite people don't trust is worse than no suite. Stable selectors, isolated state, and honest waits matter more than test count.

// 03

Speed is a feature of a test suite.

If regression takes an hour, people stop running it. Parallel execution and smart scoping keep feedback fast enough to stay in the loop.

// 04

Shift left, but bring receipts.

Early testing only helps if developers trust the signal. I work close to the code, surface failures clearly, and make the cost of a bug visible before release.

// craft

How I write a test

LoginPage.ts 
// Selectors live in the page object — the test reads like behavior.
import { Page, expect } from '@playwright/test';

export class LoginPage {
  constructor(private page: Page) {}

  async login(email: string, password: string) {
    await this.page.getByLabel('Email').fill(email);
    await this.page.getByLabel('Password').fill(password);
    await this.page.getByRole('button', { name: 'Sign in' }).click();
  }

  async expectSignedIn() {
    // assert on intent, not on a brittle CSS path
    await expect(this.page.getByTestId('user-menu')).toBeVisible();
  }
}

A test should read like a sentence about the product. I keep selectors and waits inside page objects, assert on user-facing intent rather than fragile DOM paths, and let the actual test file stay short enough that anyone on the team can tell what it's checking.
